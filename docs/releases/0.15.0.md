# PocketContext 0.15.0

Upgrade projects independently and keep different releases on one computer with
explicit checks for the selected binary, running server and database format.

- Installers refuse to replace an existing executable by default. Replacement
  requires `POCKETCONTEXT_REPLACE_VERSION` to match its inspected version; the
  caller must first stop affected processes and back up the complete projects
  with their matching binary. Checks run before downloading and before replacing.
- Local and remote clients require the same release as the running server.
  Registered profiles check the recorded server version, and managed forwards
  from another release must be stopped and restarted. Status and stop remain
  available for diagnosis and recovery.
- Database format is independent of application version. This release supports
  logical format 1 and checks application and PocketBase system migration history
  on the private working copy before PocketBase bootstrap. Unknown migrations and
  unsupported formats are refused instead of silently opening a newer database. System migrations are
  included in snapshot change detection, including migrations applied during
  PocketBase bootstrap.
- The [upgrade procedure](../upgrades.md) covers staging, clean shutdown, backup,
  replacement, profile and skill refresh, client checks and rollback. It also
  explains separate machine-local binaries for projects synced across operating
  systems and the port requirements for several readers or remote forwards.

Projects from 0.11.x–0.14.x need no data conversion. Databases from 0.10.0 and
earlier remain unsupported. This release does not add an automatic upgrade
command or automatic backups. Restore the complete backup with its matching
binary for rollback; there is no blanket binary-only downgrade guarantee.
