# PocketContext 0.9.0

Released October 22, 2026.

- A built-in private tunnel replaces the separate tailcat installation for using one server from another computer. On the agent computer, `tunnel serve` exposes only the project's port through [tailcat](https://github.com/tailscale/tailcat) 0.7.0 and prints the tunnel address; on the person's computer, `tunnel forward --address-stdin` listens on the same loopback port. Nothing else needs to be installed on either computer, and no account or administrator rights are needed.
- The tunnel admits only the project's port, proxied to the server on `127.0.0.1`: no other ports, no forwarding through the agent computer and no UDP. Traffic is end-to-end WireGuard, bootstrapped through tailcat's best-effort public relays and direct when the network allows. Sign-in is unchanged: one-time codes from `login-code`, or a password.
- The tunnel address stays the same across restarts of `tunnel serve`; its identity lives in the per-machine private cache, never in the synced project folder. `tunnel serve --new-address` replaces it and invalidates the old address. Invalid addresses are refused without being echoed, and a busy local port is an error rather than a silent change of port.
- The standalone `tailcat forward ADDRESS 8096:8096` still works with the same address, and SSH forwarding remains an alternative.
- The remote skill and CLI messages point to `tunnel forward`. Build and test commands read their tags from `build-tags.txt`, which adds the tailscale.com features the tunnel omits. The executable is about 12 MB larger.

## Upgrading

Stop the running server cleanly and back up the complete project (`pocketcontext.db`, `storage/`, and `pocketcontext.json`) before replacing the executable. Open the same project with 0.9.0; there are no schema changes. An existing standalone tailcat setup keeps working. To replace it, install 0.9.0 on both computers, stop the standalone `tailcat serve`, start `tunnel serve` and share its new address with the person's computer once, privately.

The tunnel is opt-in and runs in the foreground. Anyone holding its address can reach the port, and PocketContext still requires sign-in. Keep only one writer for the project.
