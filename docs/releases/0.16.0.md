# PocketContext 0.16.0

Reader setup now considers where commands are running, so an SSH or headless
session can finish knowledge-base setup without presenting an unusable localhost
sign-in link.

- `environment` reports session and browser capability signals without opening a
  database, starting a server or creating credentials.
- `open` skips reader setup when the session is remote, headless or uncertain,
  or no usable browser is detected. It does not start the local server, activate
  reader TCP or issue a reader code in that case.
- `--skip-reader` explicitly skips reader setup for `open` and `tunnel join`.
  Joining still saves the connection, starts its managed forward and signs in the
  CLI. `--no-browser` remains an explicit request for a manual sign-in link and
  cannot be combined with `--skip-reader`.
- Skills and client setup prompts distinguish the host from the computer where
  the user will view the reader. Already-requested remote access continues to
  the client handoff without another permission question. SSH detection alone
  does not start a tunnel.
- Reader JSON reports `browserLaunchRequested` instead of `browserOpened`,
  and reports `readerSkipped` when appropriate. Launcher dispatch does not claim
  that the page opened or the user signed in. Scripts consuming the former field
  should update to the new name and meaning.

Read [Reader setup](../reader-setup.md) for the desktop, SSH and CLI-only flows.
Existing single-user databases from 0.11.x–0.15.x need no data conversion; logical
database format 1 is unchanged. Follow [the upgrade procedure](../upgrades.md),
use matching server and client releases, and regenerate installed skills after
upgrading. Released website prompts remain unchanged at their original URLs.
