# PocketContext 0.17.0

Run an initialized project's headless server and private tunnel together as one
foreground process:

```sh
./pocketcontext serve --headless --tunnel
```

- One operating-system service can supervise both components. The command owns
  both and refuses an already running server or tunnel.
- The tunnel starts after private-socket readiness, without opening reader TCP.
  Existing identity and address are preserved.
- Ctrl+C, SIGTERM and authenticated `stop` stop both and flush the database.
  Startup and terminal component errors shut down the other component and return
  an error so the service manager can restart the process.
- `tunnel serve` remains available with its independent background-server
  behavior; stopping that tunnel still leaves its server running.
- `--tunnel` requires `--headless`. Configure an OS service explicitly for boot,
  login and crash recovery; the CLI does not install one.

See [Running a permanent service](../service.md) for a systemd user unit and
migration from two separate units. Follow [Upgrades](../upgrades.md) and use
matching client/server releases; regenerate installed skills after upgrading.

No database format, authentication protocol or dependency changes. Existing
single-user databases from 0.11.x through 0.16.2 require no data conversion.
