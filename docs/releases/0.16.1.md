# PocketContext 0.16.1

SSH-to-desktop setup now includes an explicit return checkpoint and reader
sign-in recovery instructions in the generated client prompt and installed skills.

- After preparing the server tunnel and displaying the complete desktop prompt,
  the server agent asks the user to return with confirmed reader access or the
  desktop agent's error/completion report.
- The invitation carries pairing data and instructions, not a pre-generated
  reader URL. The desktop client creates its fresh two-minute reader link after
  the connection is ready and completes sign-in before the return checkpoint.
- The desktop agent immediately displays the link when launching is unavailable
  or fails. If the user reports that the reader did not open or sign in, it
  requests a fresh link with `open --url URL --no-browser`, preserving a working
  authenticated connection rather than redeeming an invitation again.
- Completion reports distinguish CLI authentication, tunnel readiness, launch
  requests and confirmed reader access. Browser access remains pending
  verification until confirmed.

There are no database, authentication protocol or session-detection changes.
Follow [the upgrade procedure](../upgrades.md), use matching server/client
releases and regenerate installed skills. Existing single-user databases from
0.11.x through 0.16.0 need no data conversion. Released website prompts remain
unchanged at their original URLs.
