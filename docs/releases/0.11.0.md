# PocketContext 0.11.0

Released October 29, 2026.

**Breaking release.** PocketContext becomes single-user, and this release does not open databases created by earlier releases. There is no upgrade path; read [Upgrading](#upgrading) before installing it.

- One user per project. A project has exactly one account, created by `init` and required on every request; a second account is refused. It has no email to choose: `init [--port N] [--password-stdin]` asks only for a password, the reader asks only for that password, and `pocketcontext.json` no longer stores an email. Authentication stays on as before (loopback only, Host check, own-origin CORS, the local key for the CLI, single-use `open` links and `login-code` codes).
- Spaces are plain partitions of that user's knowledge, no longer an access boundary. A space has a name and can be archived; there are no Personal or Company spaces, memberships, roles or project policy. A new project starts with one space, `Default`, which is the default. The default is stored in the database (`settings`) and can be changed; it cannot be archived, and an archived space cannot become the default. Archived spaces stay readable and refuse writes. Records created without a space go to the default; references across spaces still fail like missing records, and source hashes, run keys, page slugs and publication sequences stay unique per space. See [spaces](../spaces.md).
- New commands: `spaces` (ID, name, archived, default, selected), `create-space NAME` (returns the one space already named NAME instead of creating another), `rename-space SPACE NAME`, `archive-space SPACE`, `restore-space SPACE` and `default-space [SPACE]`. `--space` and `POCKETCONTEXT_SPACE` accept a space ID or a unique name. `whoami` reports the sign-in and the selected space.
- Removed: `account`, `create-personal-space`, `--email` and `--name` on `init`, and `--email` on `open`, `login-code` and `login`. `login --url URL` signs in with the project password; `password`, `login-code`, `login --code-stdin`, `open` and `tunnel` work as before, for the same person on another computer.
- The schema has no `created_by`/`updated_by` on records, no actor in `audit_log`, and no `space_members`, `user_directory` or `project_policy` tables. `GET /api/spaces/default` returns the default space; `POST /api/spaces/personal` is gone.
- SQL reads the live database directly through read-only connections, with the column allowlist and the row, byte and time limits; per-requester SQL snapshots are gone. Search indexes are shared and built in memory: page search is scoped by publication, source search by space.
- The reader's space manager creates, renames, archives and restores spaces and makes a space the default; it never offers to archive the default. The personal-space button and roles are gone.
- The skill describes spaces as partitions and the new commands, and no longer mentions accounts or email sign-in.

## Upgrading

Databases from 0.10.0 and earlier are refused: the server stops at startup with a message naming the file and leaves it unchanged, including any unsaved working copy of an earlier release. Nothing converts them.

1. Before upgrading, while still on 0.10.0, export what you need: keep your original notes and files, or download originals and read pages with 0.10.0 (`original SOURCE --out FILE`, `page SLUG`, `sql`).
2. Install 0.11.0 and start a new project, for example `pocketcontext init --db NEW_PATH`, in a new folder or under a new database name. Keep the old project folder (and a 0.10.0 binary) if you want to read it again.
3. Ingest the sources again and let the agent rebuild the pages.
4. Run `pocketcontext skill` again to install the updated skill.

Remote clients sign in again with `login --url URL --code-stdin` (a code from `login-code` on the agent computer) or with the project password.
