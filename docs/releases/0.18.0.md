# PocketContext 0.18.0

Open the reader on a phone through a domain with HTTPS managed by the same
PocketContext binary. No separate web server or certificate tool is required.

On an initialized, stopped project:

```sh
./pocketcontext serve --headless --domain knowledge.example.com
```

- HTTPS hosting is opt-in. Default local and private-tunnel workflows remain
  available. Add `--tunnel` when both forms of access are wanted.
- PocketContext obtains and renews a Let's Encrypt certificate for the configured
  domain. Public TCP ports 80 and 443, suitable DNS, and an always-on reachable
  host are required. HTTP serves certificate challenges and HTTPS redirects.
- Public access exposes the authenticated reader and its supported APIs; local
  administration and the embedded administrator dashboard remain private.
- Run `open --public` locally to create a short-lived phone sign-in link without
  opening a browser on the server.
- Certificate state stays in the private machine cache, outside the synced
  project. Existing database snapshot, publication, and conflict guards remain.
- One operating-system service supervises the foreground process. Setup agents
  configure service startup and verify the public URL before declaring success.

See [HTTPS hosting](../https.md), [permanent services](../service.md), and
[upgrades](../upgrades.md). Upgrade clients to the matching release and regenerate
installed skills. Existing single-user databases require no data conversion.

This release adds phone access to the reader. Agent chat is not included.
